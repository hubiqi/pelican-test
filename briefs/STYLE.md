# STYLE.md — 全片共用规格（所有版块都必须遵守）

这份文件是 20 个版块的**共同契约**。任何一个版块单独看要成立，合起来要像同一支片子。

---

## 1. 画面空间

| 项 | 值 |
|---|---|
| 设计方格 | **1000 × 1000**（`src/scenes/*.js` 里的 `render(g, ctx)` 直接在这个坐标里画） |
| 输出 | **1920 × 1080**，p5 会按 `cover` 放大 ×1.92 并上下各裁 218.75 |
| 安全带 | **y ∈ [219, 781]**，所有关键信息（脸、字、梗）必须在这里 |
| 默认地面线 | `kit.GROUND_Y = 690`（车轮着地的那条线） |
| 能看到的画框 | 左右立柱在 `x ∈ [0, 44]` 与 `[956, 1000]`（穿框时观众看到的就是这两根） |

```js
render(g, ctx)   // g: p5.Graphics(1920×1920, 已 scale 1.92)；ctx 见下
```

### ctx 提供什么

| 字段 | 含义 |
|---|---|
| `ctx.t` | 本版块内的局部时间 0 → 6 秒 |
| `ctx.u` | 0 → 1 的进度（`t / 6`） |
| `ctx.tGlobal` | 全片绝对时间（做跨片连续动作用） |
| `ctx.rig` | 当前姿势 `PEL.rig.solve(tGlobal)` |
| `ctx.scroll` | 路面滚动距离（设计单位，配合车轮转速） |
| `ctx.index` | 版块序号 1…20 |
| `ctx.still` | 结尾展墙用的定格图（一般不用） |

**画面必须是 `t` 的纯函数**：不吃帧间状态、不用 `random()`（要随机就用 `kit.hash` / `kit.noise1`），
这样进度条拖动、逐帧导出、接触表才能一致。

## 2. 时间与节拍（120 BPM，一小节 2 秒）

每个版块 **3 小节 = 6 秒**，内部结构固定：

| 小节 | 局部时间 | 干什么 |
|---|---|---|
| 第 1 小节 | 0.0 – 2.0 | **进场**：从画框左侧骑入，环境先立起来 |
| 第 2 小节 | 2.0 – 4.0 | **梗 / 高光**：本版最该被记住的那一下（可以放慢、定格） |
| 第 3 小节 | 4.0 – 6.0 | **离场**：骑向右侧下一道画框 |
| 强拍 | 0.0 / 2.0 / 4.0 | 打点：转场、闪光、字弹出、音效落点 |

- 脚踏一圈 = 两拍 = **1 秒**；车轮与脚踏 1:1（`ctx.rig.theta`）
- 需要顿挫感的版块（皮影、8-bit、聊天动图）：内部用 `PEL.beat.quantize(t, 8~12)` 量化，
  **但镜头平移不量化**
- 车铃、链条声可以当全片贯穿的打击乐（音效在阶段 4）

## 3. 统一的东西

### 3.1 标题卡

每个版块一张，中文名 + 英文名 + 年代，1080p 下必须清晰可读（中文 ≥ 40 设计单位，
即屏幕上 ≥ 77 px）。默认样式用 `kit.titleCard`，允许各版块换成自己时代的排版：

```js
kit.titleCard(g, {
  x: 74, y: 330, zh: '撒哈拉岩画', en: 'Sahara Rock Art', era: '约前 4000 · 塔西里高原',
  ink: [42,26,16], accent: [206,120,58],
});
```

### 3.2 鹈鹕与自行车

**统一用 `PEL.rig.solve(ctx.tGlobal)` 取姿势，不要自己算脚踏相位**，否则换版块时动作会断。
`solve` 返回一份完整骨骼（关节坐标 + 车架几何 + 喙 / 喉囊 / 翅），各版块用**自己的画法**把它画出来：

```js
const p = ctx.rig;            // 或 PEL.rig.solve(t)
g.push(); g.translate(x, kit.GROUND_Y); g.scale(s);
PEL.rig.paint(g, p, 'fill', { ink, body, accent, w: 2.4 });  // 中性版，可直接用或完全重画
g.pop();
```

- 车的尺寸：轴距 236、轮半径 56、车把在 `(96, -160)` —— 与 `kit.GROUND_Y` 对齐即可着地
- **造型必须随风格变**：诺斯费拉图只出现影子；皮影是镂空剪影；8-bit 是像素块；
  示波器是发光矢量线；竖屏短视频是低清抖动
- 每版至少要有一只「自己的鹈鹕」出现在画面里（除非简报另有说明），否则观众会丢失主角

### 3.3 画框

每版块左右两端各一根画框（`x ∈ [0,44]`、`[956,1000]`），画法按时代来：
岩画是岩壁边缘、埃及是柱式、汉画是石框、浮世绘是版画边框、8-bit 是像素边、
聊天窗口是窗口边框、代码美学是编辑器 gutter。
转场时观众会看到这两根柱子从画面中间滑过，所以**别把画面画成完全连续的**。

### 3.4 水墨模块（3、4、5、6、9 共用）

共用一套渲染，但笔法不同：

| 版块 | 底材 | 笔法 |
|---|---|---|
| 3 汉画像石拓片 | 黑底白线的拓片（纸纤维压痕 + 石花） | 阴刻轮廓，线条粗壮、边缘毛 |
| 4 唐代白描 | 米色绢 | 纯墨线，细而长，飘带翻飞（`kit.tapered`） |
| 5 宋代山水 | 绢本淡墨 | 皴法、巨峰占 2/3 画面，鹈鹕小到几乎看不见 |
| 6 清明上河图 | 淡彩 | 界画（建筑直线）+ 人物点景 + 笛子锣鼓般的市井 |
| 9 八大山人 | 生宣留白 | 寥寥几笔、大片空白、翻白眼 |

共用件：`kit.paper`（宣纸纹理）、`kit.stroke`（毛边线，`dry` 参数做飞白）、
`kit.bleed`（墨色晕染）、`kit.tapered`（锥形线，画飘带 / 脖子）。

## 4. 性能预算

- 单个版块一帧的绘制时间目标 **< 12 ms**（1080p，桌面 Chrome）
- 禁止每帧 `createGraphics`；需要缓存（纸张纹理、烘焙图案）就在 `init` 时做一次
- 逐像素循环最多 1000×1000 一轮，且必须能用 `kit.grain` 替代时就替代
